## 1. 概述

### 1.1 测试目的

本文档定义了 TC234 A/B 双分区 Bootloader 的完整测试方案，覆盖：
- UDS 诊断服务的功能正确性
- CAN TP 传输层的协议一致性
- Flash 刷写的数据完整性与安全性
- 双分区启动管理的可靠性
- 安全机制的健壮性

### 1.2 测试范围

| 模块 | 测试重点 | 参考源码 |
|------|----------|----------|
| UDS 应用层 | 服务分发、会话管理、安全访问、NRC | [`uds_app.c`](BootLoader_dualBank/AppSw/Tricore/App_UDS/uds_app.c) |
| CAN TP | 帧类型处理、超时、序列号、流控 | [`uds_tp.c`](BootLoader_dualBank/AppSw/Tricore/App_UDS/uds_tp.c) |
| Flash 驱动 | 擦除、写入、PSPR 重定位 | [`Flash.c`](BootLoader_dualBank/AppSw/Tricore/Tc234_Modules/Flash/Flash.c) |
| 双分区管理 | 标志区读写、Bank 验证、跳转、回滚 | [`Boot_DualBank.c`](BootLoader_dualBank/AppSw/Tricore/App_bootloader/Boot_DualBank.c) |
| Bootloader 核心 | 启动流程、主循环、复位 | [`App_bootloader.c`](BootLoader_dualBank/AppSw/Tricore/App_bootloader/App_bootloader.c) |

### 1.3 测试等级

| 等级 | 名称 | 说明 |
|------|------|------|
| L1 | 单元测试 | 针对单个函数/模块的测试 |
| L2 | 集成测试 | 模块间交互测试（如 UDS + TP + CAN） |
| L3 | 系统测试 | 完整刷写流程、启动流程测试 |
| L4 | 验收测试 | 按 OEM 规范执行的全量测试 |

## 3. UDS 诊断服务测试用例

### 3.1 DiagnosticSessionControl (0x10)

#### TC-0x10-001: 默认会话进入

| 项目 | 内容 |
|------|------|
| **目的** | 验证默认会话进入功能 |
| **前置条件** | ECU 上电，处于 Bootloader 模式 |
| **测试步骤** | 1. 发送: `74C  [8]  02 10 01 AA AA AA AA AA` |
| **期望结果** | 响应: `75C  [8]  02 50 01 AA AA AA AA AA` |
| **通过标准** | 正响应，当前会话 = Default Session |

#### TC-0x10-002: 编程会话进入（需 Level 1 解锁）

| 项目 | 内容 |
|------|------|
| **目的** | 验证编程会话进入条件检查 |
| **前置条件** | 默认会话，未解锁 Level 1 |
| **测试步骤** | 1. 发送: `02 10 02` |
| **期望结果** | 响应: `03 7F 10 33` (NRC_SECURITY_ACCESS_DENIED) |
| **通过标准** | 正确返回安全访问拒绝 |

#### TC-0x10-003: 编程会话进入（已解锁 Level 1）

| 项目 | 内容 |
|------|------|
| **目的** | 验证编程会话正常进入 |
| **前置条件** | 扩展会话，已解锁 Level 1 |
| **测试步骤** | 1. 发送: `02 10 02` |
| **期望结果** | 响应: `02 50 02` |
| **通过标准** | 正响应，当前会话 = Programming Session |

#### TC-0x10-004: 扩展会话进入

| 项目 | 内容 |
|------|------|
| **目的** | 验证扩展会话进入 |
| **前置条件** | 默认会话 |
| **测试步骤** | 1. 发送: `02 10 03` |
| **期望结果** | 响应: `02 50 03` |

#### TC-0x10-005: 抑制正响应位

| 项目 | 内容 |
|------|------|
| **目的** | 验证 suppressPositiveResponse 位处理 |
| **前置条件** | 默认会话 |

| **期望结果** | 无响应（或应用层正确处理 xDataLen=0） |

#### TC-0x10-006: 不支持子功能

| 项目 | 内容 |

| **期望结果** | 响应: `03 7F 10 12` (NRC_SUBFUNCTION_NOT_SUPPORTED) |
| **通过标准** | 正确返回不支持子功能 |

#### TC-0x10-007: S3 超时回默认会话

| 项目 | 内容 |
|------|------|
| **目的** | 验证 S3 超时机制 |
| **前置条件** | 扩展会话 |
| **测试步骤** | 1. 进入扩展会话<br>2. 等待 5 秒不发送任何请求<br>3. 发送 `02 10 01` |
| **期望结果** | 步骤 2 后安全等级归零；步骤 3 正常响应 |
| **通过标准** | S3 超时后自动回到 Default Session + NONE_SECURITY |

| 项目 | 内容 |
|------|------|
| **目的** | 验证正确 Key 解锁功能 |
| **前置条件** | 已请求 Seed，记录 Seed 值 |

| **期望结果** | 响应: `02 67 02` |
| **通过标准** | 正响应，安全等级 = Level 1 |

#### TC-0x27-003: Level 1 Key 验证（错误 Key）

| 项目 | 内容 |
|------|------|
| **目的** | 验证错误 Key 的处理 |
| **前置条件** | 已请求 Seed |
| **测试步骤** | 1. 发送错误的 Key: `06 27 02 00 00 00 00` |
| **期望结果** | 响应: `03 7F 27 35` (NRC_INVALID_KEY) |
| **通过标准** | 正确返回无效 Key |

#### TC-0x27-004: 安全访问锁定（3 次错误）

| 项目 | 内容 |
|------|------|
| **目的** | 验证连续错误 Key 后的锁定机制 |
| **前置条件** | 扩展会话 |

| **通过标准** | 3 次错误后锁定 10 秒 |

#### TC-0x27-005: Level 2 Seed 请求（编程会话）

| 项目 | 内容 |
|------|------|
| **目的** | 验证 Level 2 解锁（刷写必需） |
| **前置条件** | 编程会话，已解锁 Level 1 |
| **测试步骤** | 1. 发送: `02 27 03` |
| **期望结果** | 响应: `06 67 03 xx xx xx xx` |
| **通过标准** | 正响应，Seed 有效 |

## 4. CAN TP 传输层测试用例

### 4.1 单帧传输 (SF)

#### TC-TP-001: 单帧请求与响应

| 项目 | 内容 |
|------|------|
| **目的** | 验证单帧收发功能 |
| **前置条件** | ECU 在线，默认会话 |
| **测试步骤** | 1. 诊断仪发送 SF: `02 10 01` |
| **期望结果** | ECU 响应 SF: `02 50 01` |
| **通过标准** | 正确解析 PCI=0x02，数据长度=2 |

### 4.2 多帧传输 (FF + CF + FC)

#### TC-TP-002: 首帧 + 流控 + 连续帧（接收方向）

| 项目 | 内容 |
|------|------|
| **目的** | 验证 ECU 接收多帧数据 |
| **前置条件** | 编程会话，已解锁 Level 2 |
| **测试步骤** | 1. 诊断仪发送 FF: `10 20 34 00 44 A0 02 00 00` (总长 32 字节)<br>2. 观察 ECU 是否发送 FC: `30 00 05` (CTS, BS=0, STmin=5ms)<br>3. 诊断仪发送 CF 序列: `21 xx xx xx xx xx xx` ... |
| **期望结果** | ECU 正确重组 32 字节数据，调用 RequestDownload0x34 |
| **通过标准** | 无 N_WRONG_SN、N_TIMEOUT_Cr 错误 |

#### TC-TP-003: 流控 Block Size 限制

| 项目 | 内容 |
|------|------|
| **目的** | 验证 BS 非零时的分段传输 |
| **前置条件** | 编程会话 |
| **测试步骤** | 1. 修改 ECU 配置 BS=8<br>2. 诊断仪发送长数据（> 8*7 = 56 字节） |
| **期望结果** | 每发 8 个 CF 后，ECU 发送 FC 帧允许继续 |
| **通过标准** | 传输完成，无 N_TIMEOUT_Bs |

### 4.3 超时测试

#### TC-TP-004: N_Cr 超时（等不到 CF）

| 项目 | 内容 |
|------|------|
| **目的** | 验证 N_Cr 超时处理 |
| **前置条件** | 编程会话 |
| **测试步骤** | 1. 诊断仪发送 FF<br>2. ECU 回复 FC<br>3. 诊断仪故意不发送 CF，等待 > 150ms |
| **期望结果** | ECU 触发 N_TIMEOUT_Cr，丢弃当前传输，回到 IDLE |
| **通过标准** | TP 层返回超时错误，UDS 层不处理不完整数据 |

#### TC-TP-005: N_Bs 超时（等不到 FC）

| 项目 | 内容 |
|------|------|
| **目的** | 验证发送方 N_Bs 超时 |
| **前置条件** | 编程会话，ECU 需要发送长响应 |
| **测试步骤** | 1. 触发 ECU 发送多帧响应（如 0x22 读长 DID）<br>2. 诊断仪不回复 FC |
| **期望结果** | ECU 在 75ms 后触发 N_TIMEOUT_Bs，停止发送 |
| **通过标准** | 发送状态机回到 IDLE |

### 4.4 序列号错误

#### TC-TP-006: CF 序列号不连续

| 项目 | 内容 |
|------|------|
| **目的** | 验证 SN 错误检测 |
| **前置条件** | 编程会话 |
| **测试步骤** | 1. 诊断仪发送 FF<br>2. ECU 回复 FC<br>3. 诊断仪发送 CF#1 (SN=1)<br>4. 诊断仪发送 CF#3 (SN=3，跳过 2) |
| **期望结果** | ECU 检测到 SN 不连续，返回 N_WRONG_SN，丢弃传输 |
| **通过标准** | TP 层报告序列号错误 |

### 11.3 刷写脚本使用说明

#### Python 刷写脚本 [`shuaxie.py`](BootLoader_dualBank/shuaxie.py)

```bash
# 在 ZCANPro 中加载脚本并运行 __zxdoc_main__()
# 或在 Python 环境中调用 do_flash_process()
```

**脚本流程**：
1. `10 01` — 默认会话
2. `10 03` — 扩展会话
3. `27 01/02` — Level 1 解锁
4. `31 01 FF FD` — 检查编程条件（动态确定 targetBank）
5. `85 02` — 关闭 DTC
6. `10 02` — 编程会话
7. `27 03/04` — Level 2 解锁
8. `2E F1 5A` — 写指纹
9. `31 01 FF 00` — 逐个擦除目标 Bank Sector
10. `34/36/37` — 文件下载（ZXDoc file_download API）
11. `31 01 DF FF` — 验证并激活（脚本中可选启用）
12. `11 01` — ECU Hard Reset

**动态 Bank 选择**：
- 脚本根据 `0x31 01 FF FD` 响应中的 `targetBank` 字段自动切换 `TARGET_BANK`
- `0x0A` → Bank A
- `0x0B` → Bank B
